# unplugin-deno

## 0.1.0

### Minor Changes

- ee09f58: First release: Deno's module resolution for Vite 8 and 7, Rolldown (and tsdown), Rollup 4, esbuild, webpack 5 (5.108+), Rspack 2 and Rsbuild 2, with the bundler running on Node.js, Deno or Bun and no Deno installation needed.
  
  - `jsr:`, `npm:` (subpaths, CommonJS), `https:`, `data:` and `node:` imports, and `with { type: "text" | "bytes" | "css" }` import attributes in static and dynamic imports on every supported bundler.
  - `deno.json` import maps and scopes, which win over `node_modules`; workspaces with glob members, member-scoped imports and `links`; `deno.lock` pins and integrity checks of remote modules; without a lockfile, the versions `deno install` would pick (`minimumDependencyAge`).
  - npm packages from Deno's global cache or installed into `node_modules` (`nodeModulesDir: "auto"`), resolved by the bundler itself, so `exports`, `browser` and `sideEffects` apply; with `jsrDepsInNodeModules`, `jsr:` imports resolve to the `@jsr/<scope>__<name>` packages in `node_modules`.
  - Remote and JSR modules written as plain files with readable source maps under `node_modules/.unplugin-deno` and reused by later builds.
  - Engines: the bundled `@deno/loader` by default; `engine: 'auto'` uses an installed Deno (2.8.3+, `denoBinary`) for what the loader lacks (`catalog:` versions, globs in `links`, `jsrDepsInNodeModules`, a `JSR_URL` registry), and `engine: 'deno'` always does. Neither writes `deno.lock`.
  - Deno server output (`platform: 'deno'`, Vite and Rsbuild server environments of a project with a `deno.json`, Node.js targets on webpack and Rspack, webpack's `target: 'deno'`, esbuild's `packages: 'external'`): `npm:` and `jsr:` imports stay external, pinned to exact versions, so the output runs under `deno run --cached-only`; `emitDenoConfig` writes a `deno.json` and a `deno.lock` of the externals next to the output for `deno run --frozen --cached-only`.
  - Deno's semantics for local code: the `compilerOptions.jsx*` settings of `deno.json` configure the bundler's JSX transform unless its config sets JSX (`"precompile"` compiles with the automatic runtime and a warning); `.wasm` module imports are instantiated like in Deno (`wasm`); `import.meta.main` is `false` outside entry modules (`importMetaMain`); `env: { prefix: 'PUBLIC_' }` inlines `Deno.env.get("PUBLIC_X")` and `process.env.PUBLIC_X` into browser bundles from the process and `.env` files.
  - Lockfile and offline: `lockfile: 'frozen'` (and `'auto'` when `CI` is set or `deno.json` sets `"lock": { "frozen": true }`) fails with `LOCKFILE_FROZEN_DRIFT` when an import resolves to something `deno.lock` does not record; `cachedOnly` never downloads and names the command that fills Deno's cache (`CACHED_ONLY_MISS`, `NOT_IN_LOCKFILE`); remote imports are limited to Deno's `--allow-import` hosts plus the hosts the lockfile and import maps name (`allowImport`, `DISALLOWED_HOST`).
  - Private registries: `NPM_CONFIG_REGISTRY` and `.npmrc` auth tokens, a `fetch` option for proxies and authentication, and `JSR_URL` with `DENO_AUTH_TOKENS` through the `deno` engine.
  - Diagnostics: errors with stable codes and hints; warnings for `Deno.*` in browser code (`denoGlobals: 'error'` fails with `PLATFORM_INCOMPATIBLE`), `node:` builtins imported into browser bundles, npm native addons (kept external), npm packages bundled in several versions, and a `node_modules` another package manager installed when Deno manages it; `debug: true` or `DEBUG=unplugin-deno` prints what the plugin found.
  - Vite: a platform per environment, JSR, npm, `https:` and `data:` dependencies prebundled in one optimizer run, full reloads when `deno.json` or `deno.lock` change, workspace members outside the Vite root, worker bundles, and path-like import-map keys in CSS `@import`.
  - esbuild: `deno.json` found from `absWorkingDir`, `esbuild.context()` rebuilds that pick up `deno.json` changes, and esbuild's own `external` option respected.
  - webpack and Rspack: the scheme externals of `externalsPresets.web` and `target: 'deno'` are taken over (with an info line), webpack's `experiments.buildHttp` keeps its URLs, watch mode reloads `deno.json`, and webpack's persistent cache tracks the config files. A TypeScript loader that keeps import attributes is needed (`esbuild-loader` with `target: 'esnext'`, or `builtin:swc-loader` with `keepImportAttributes`).
  
  Not included yet: Bun.build and Farm (their entries do nothing), `unplugin-deno/register` and `unplugin-deno/api` (they throw), and `jsx: 'deno'` (JSX precompilation for local files). The `deno` engine does not pass its tests on Windows yet.
